# pihta-channel-max

Тонкий MAX-канал системы бронирования «Пихта». Ничего не знает про брони и базу:
принимает вебхук от MAX, спрашивает ядро (`pihta-core`), рисует экран вложениями MAX.

## Переменные окружения

| Ключ | Значение |
|---|---|
| `MAX_BOT_TOKEN` | токен бота MAX (вводится в панели) |
| `CORE_URL` | `https://<домен ядра>` |
| `CORE_API_TOKEN` | общий секрет канала и ядра |
| `WEBHOOK_SECRET` | секрет подписи вебхука MAX (`X-Max-Bot-Api-Secret`) |
| `WEBHOOK_URL` | `https://<домен канала>/webhook` — канал сам подпишется при старте |
| `PORT` | внутренний порт (3000) |
| `RELEASE` | метка релиза в логе |

## Маршруты

- `GET /health` — живость для платформы;
- `POST /webhook` — обновления MAX (проверка секрета, ответ 200 быстро);
- `POST /deliver` — доставка уведомлений из ядра (`X-Core-Token`), с повтором на 429/5xx.

## Что умеет

- `bot_started` и `/start` → полное меню;
- текст → `POST /api/v1/text`, контакт (vcf) → `/api/v1/contact`, кнопка → `/api/v1/screen`;
- экран редактируется на месте (`PUT /messages`), баннеры загружаются один раз и кешируются;
- служебные подтверждения — `POST /answers` с `notification` (плашка, не сообщение);
- российский корневой сертификат для TLS MAX — в `ca/`.
